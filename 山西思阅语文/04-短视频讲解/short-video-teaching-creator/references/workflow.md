# Workflow

Use this workflow for question-based short-video teaching production.

## 1. Confirm Inputs

Confirm or infer:

- source question file or folder
- reference answer file
- scoring note or rubric file when available
- knowledge-base or teaching-reference materials
- existing short-video style sample, if any
- output directory
- whether the user wants Word only, PPT only, or both

Default assumption: if the user asks for “可以直接拍摄用”, produce both Word and PPT.

## 2. Lock Scope

Keep the job narrow:

- one question
- one sub-question
- one teaching point

Do not drift into full-paper analysis unless the user explicitly asks for it.

## 3. Extract Source Facts

Locate and preserve:

- original question wording
- surrounding passage or material
- official answer
- scoring language

If useful, capture visual crops of the original question for slides.

## 4. Solve Before Teaching

Before writing teaching copy:

1. solve the question independently
2. compare with the official answer
3. identify the exact scoring points
4. identify the gap between surface answer and full-score answer

This gap usually becomes the teaching hook.

## 5. Extract The Transferable Method

The final explanation should teach a method, not just a single answer.

Examples:

- “from prior plot, side action, and title theme”
- “first identify the wrong behavior, then the broken rule, then the root value”
- “read the scoring note backward to see what depth is rewarded”

Phrase the method so it can be reused on the next similar question.

## 6. Match The House Style

If the user provides existing scripts or a named teacher style, extract:

- opening rhythm
- value framing
- sentence length
- explanation depth
- answer reveal pattern
- closing summary pattern

Do not mimic filler; preserve only the useful repeatable structure.

## 7. Build The Word Script

The script should include:

- title
- exam-context opening
- question restatement
- layered explanation
- scoring-point reveal
- full answer
- method summary
- optional slide cues

The document must read like a direct shooting script, not like an essay or internal notes.

## 8. Build The PPT

Common slide sequence:

1. cover / value framing
2. original question
3. low-score trap
4. method overview
5. reasoning layer 1
6. reasoning layer 2
7. reasoning layer 3
8. deep structure / progression
9. final answer and keyword recap

Adapt the count as needed, but keep one teaching objective per slide.

## 9. QA Before Delivery

Check:

- source accuracy
- answer alignment with rubric
- script can be spoken naturally
- slides are readable in recording conditions
- no overflow or tiny labels
- no unnecessary footer noise
- visual hierarchy is obvious

## 10. Iterate On Feedback

Common revision requests:

- enlarge headers or labels
- reduce clutter
- strengthen visual contrast
- simplify slide density
- keep the logic but clean the layout

When revising, preserve the teaching spine and update only the presentation layer unless the feedback affects content accuracy.
